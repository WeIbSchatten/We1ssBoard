**AmneziaWG** — форк WireGuard с обфускацией трафика (мусорные пакеты,
случайное дополнение и изменённые служебные значения протокола), чтобы для DPI
туннель не выглядел как WireGuard. Его выбирают там, где обычный WireGuard
блокируется, а туннель того же устройства, но с другим отпечатком проходит.

<Callout type="info">
  AmneziaWG работает **внутри процесса панели** — `amneziawg-go` поверх
  сетевого стека в пространстве пользователя (gVisor), а не модуля ядра. Не нужны
  сборка DKMS, совместимость с Secure Boot и доступ к сети или ядру хоста,
  поэтому в контейнере он работает так же, как на голом сервере. Расшифрованный
  трафик каждого пира идёт в его собственное loopback-входящее SOCKS5 в Xray, так
  что маршрутизация, sniffing и статистика по клиенту — это механизмы самого Xray,
  как у входящих любого другого протокола, а не отдельный путь в коде.
</Callout>

## Основные настройки

### Сервер / интерфейс

| Поле                     | Что это                                                                  |
| ------------------------ | ------------------------------------------------------------------------ |
| **Подсеть**              | IPv4-подсеть туннеля (например, `10.8.1.0/24`); каждый клиент получает адрес из неё. |
| **MTU**                  | MTU интерфейса. Оставьте значение по умолчанию, если нет причин его менять. |
| **DNS (основной/запасной)** | Подставляется в скачиваемые конфигурации клиентов; самому интерфейсу сервера DNS не нужен. |
| **Внешний интерфейс**    | Сетевая карта хоста, на которую добавляется IPv6-адрес пира при включённом IPv6 (см. ниже). Оставьте пустым для автоопределения. |

### Обфускация (AmneziaWG 3.1)

Значения должны совпадать на обоих концах туннеля, поэтому сервер хранит их
один раз, а каждая конфигурация клиента их наследует. Панель генерирует
случайный набор сама (есть кнопка **перегенерировать**) — одно и то же
значение везде лишает обфускацию смысла: со временем DPI выучит этот отпечаток.

| Поле         | Что это                                                                      |
| ------------ | ---------------------------------------------------------------------------- |
| **Jc**       | Число мусорных пакетов перед рукопожатием.                                   |
| **Jmin/Jmax** | Диапазон размеров (байты) этих пакетов. `Jmin` не может быть больше `Jmax`. |
| **S1/S2**    | Дополнение пакетов начала и ответа рукопожатия, `0`-`1552` / `0`-`1608`: пакеты занимают `148 + S1` и `92 + S2` байт и должны помещаться в 1700-байтовый буфер приёма amneziawg-go на iOS. Панель также не принимает `S1 + 56 = S2`, при котором оба пакета в сети одного размера (сам amneziawg-go это допускает). Исходящее AmneziaWG берёт значения удалённого сервера как есть, до `65535`. |
| **S3**       | Дополнение ответа cookie, `0`-`1636`: ответ занимает `64 + S3` байт и должен помещаться в 1700-байтовый буфер приёма amneziawg-go на iOS. Исходящее, как и с S1/S2, берёт значение удалённого сервера до `65535`. |
| **S4**       | Дополнение транспортных пакетов (данных), `0`-`32`.                          |
| **H1-H4**    | Значения заголовка, заменяющие поле типа сообщения WireGuard. Каждое — одно целое число или диапазон `low-high`, и четыре значения не должны пересекаться — иначе amneziawg-go и модуль ядра отказываются поднимать устройство целиком. `1`-`4` — собственные типы WireGuard и значение движка для пустого поля: допустимо, но без HeaderProtectionKey поле типа тогда выглядит как в обычном WireGuard. |
| **I1-I5**    | Необязательные сигнатурные пакеты — случайные байты перед рукопожатием, например `<r 148>`. Сгенерированные наборы заполняют только `I1`, как генератор самой Amnezia. |
| **HeaderProtectionKey** | Ключ base64 длиной 32 байта для механизма защиты заголовков 3.0. Должен совпадать во всех конфигурациях клиентов; пустое значение отключает защиту. |
| **ContentPaddingAddition** | Одно целое число или диапазон байт `low-high` — дополнительное дополнение пакетов с данными. Генератор держит его `<= 64`, чтобы туннель с MTU 1420 не фрагментировался. |
| **RekeyAfterTime / RekeyTimeout / RejectAfterTime / KeepaliveTimeout / MaxHandshakeAttempts** | Случайные тайминги рукопожатия: каждое — диапазон `low-high` (секунды; для последнего — попытки), из которого пир выбирает значение, чтобы время сессий перестало быть отпечатком WireGuard. Любое значение `RekeyAfterTime` должно быть меньше любого значения `RejectAfterTime`. Пустое поле оставляет значение WireGuard. |
| **RandomTrailers** | Добавляет случайное число байт в конец каждого пакета.                  |
| **DisableCookies** | Не отправлять ответы cookie — убирает заметный для DPI тип сообщений WireGuard ценой защиты рукопожатия от флуда. |

<Callout type="info">
  Если вводите параметры обфускации вручную, а не берёте сгенерированные, следите,
  чтобы `H1`-`H4` **не пересекались** и были больше `4`, и проверьте
  `S1 + 56 != S2` — с неверным значением встроенный интерфейс вообще не
  поднимется.
</Callout>

<Callout type="warn">
  Параметры 3.1 требуют **клиента с поддержкой 3.1** — приложения Amnezia
  соответствующей версии; если очистить поля 3.1, получится конфигурация, которую
  понимают и старые клиенты. К хосту требований по версии нет: панель поставляет
  свой закреплённый `amneziawg-go`, а не тот, что установлен в системе.
</Callout>

## Настройка в панели

<Steps>

<Step>
### Создайте входящее

Создайте новое входящее, выберите протокол **AmneziaWG** и задайте порт и
подсеть туннеля.
</Step>

<Step>
### Оставьте обфускацию по умолчанию (или перегенерируйте)

Панель сама заполняет случайный набор параметров, допустимый для ядра. Нажмите
**Перегенерировать**, если нужен новый; вручную их править незачем без особой
причины.
</Step>

<Step>
### Добавьте клиента

У каждого клиента своя пара ключей и адрес в туннеле. Скачайте `.conf` клиента
или скопируйте его ссылку (`vpn://…`, импортируется официальными приложениями
AmneziaWG/AmneziaVPN) из списка клиентов.
</Step>

<Step>
### Необязательно: включите IPv6

При включённом IPv6 каждый клиент получает, помимо IPv4, адрес из заданной
IPv6-подсети. Панель добавляет этот адрес на сетевую карту внешнего интерфейса,
так что исходящие соединения идут с собственным публичным IPv6 пира — NAT66 не
нужен.
</Step>

<Step>
### Необязательно: пробросьте порты клиенту

Задайте клиенту пробрасываемые порты (например, `80, 443, 8000-8100`), и на
хосте откроется настоящий listener, который передаёт этот трафик прямо на адрес
клиента в туннеле, — удобно, если клиенту нужно открыть сервис через сервер.
</Step>

</Steps>

Трафик любого входящего AmneziaWG и так идёт через Xray — каждый пир передаёт
его в своё loopback-входящее SOCKS5 с тегом самого входящего AmneziaWG, поэтому
на странице [маршрутизации](/docs/operations/outbounds-routing) оно видно как
обычный источник, как входящее любого другого протокола. Отдельного
переключателя для этого нет: в отличие от туннеля в ядре, расшифрованному
трафику пира больше некуда идти в интернет.

Скачиваемый `.conf` клиента (его же в base64url кодирует ссылка `vpn://`)
выглядит так:

```ini title="client .conf"
[Interface]

DNS = 8.8.8.8, 8.8.4.4
Jc = 4
Jmin = 65
Jmax = 220
S1 = 87
S2 = 44
S3 = 21
S4 = 9
H1 = 463065432
H2 = 912345678
H3 = 1345678901
H4 = 1987654321
I1 = <r 148>
HeaderProtectionKey = 8Iu83eHDA3fMKKSGaEsVW9Ycd2lYYzc0MYlk1jJTvE4=
ContentPaddingAddition = 17-49
RekeyAfterTime = 111-139
RekeyTimeout = 4-7
RejectAfterTime = 187-251
KeepaliveTimeout = 9-14
MaxHandshakeAttempts = 19-36

DisableCookies = on

# my-client
[Peer]
PublicKey = <server public key>
AllowedIPs = 0.0.0.0/0, ::/0
Endpoint = your-server:443
PersistentKeepalive = 25
```

## Несколько узлов (подузлы)

Входящее AmneziaWG можно создать на подузле или клонировать туда. Интерфейс
запускает панель самого узла, поэтому на узле должна быть панель **v3.7.0** или
новее; главная панель отказывает более старому узлу и узлу, который ещё не
сообщил свою версию. `forwardedPorts` клиента проверяются по портам, занятым на
этом узле.
